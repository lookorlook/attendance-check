## 通用规则

以下规则适用于所有国家：

### 数据源规则

#### 数据1（系统打卡）
- 来源：打卡系统导出Excel
- 结构：C列工号、D列姓名、E列日期时间（纵向展开）
- 处理：每天取**最早时间作为上班**、**最晚时间作为下班**
- 跨日识别：最晚时间在 0:00-5:00 之间视为前一天下班时间

#### 数据2（线下登记）
- 来源：HR线下录入的PLANNING表格
- 结构：A列=姓名，1-30日横向展开
- 时间格式：`8h-16h06`（上班-下班，可含/不含分钟）
- 请假标记：各国自定义（通过JSON配置）

#### 工号映射
- 工号映射Excel文件（可选）
- 第3行起：A列=数据2姓名，B列=数据1姓名
- 当无映射文件时，使用单词级模糊匹配

### 数据合并优先级

| 场景 | 处理方式 |
|------|----------|
| 同日都有数据（数据1≥2次打卡） | 数据1优先 |
| 数据1仅1次打卡（缺卡） | 降级到数据2 |
| 仅有数据2 | 直接用数据2 |
| 仅有请假标记 | 标记为请假 |
| 无法识别标记 | 标记为"待确认" |
| 无数据 | 标记为无数据 |

### TOIL（调休补足）规则

#### Excel批注解析
当数据2的单元格中包含批注（Comment），自动扫描以下模式：

| 模式 | 解析 | 处理 |
|------|------|------|
| `2h30 de récup` | 2.5h TOIL | 加到实际工时 |
| `TT` / `Télétravail` | 远程工作 | 显示标识 |
| `Badge oublié` | 忘打卡 | 显示标识 |
| `Rdv médical` | 就医 | 显示标识 |

# 比利时考勤规则说明

## 数据源规则

### 数据1（系统打卡）
- 来源：打卡系统导出Excel
- 结构：C列工号、D列姓名、E列日期时间（纵向展开）
- 处理：每天取**最早时间作为上班**、**最晚时间作为下班**
- 跨日识别：最晚时间在 0:00-5:00 之间视为前一天下班时间

### 数据2（线下登记）
- 来源：HR线下录入的PLANNING表格
- 结构：A列=姓名，1-30日横向展开
- 时间格式：`8h-16h06`（上班-下班，可含/不含分钟）
- 请假标记：`CM`/`VA`/`OFF`/`ABSENT`/`Congé mariage`等
- 批注：Excel单元格批注中的 `2h30 de récup` 自动解析为TOIL补足

> 注意：数据1和数据2的姓名格式可能不同（数据1为系统英文大写，数据2为法文格式），通过工号映射或模糊匹配关联。

### 工号映射
- 工号映射Excel文件（可选）
- 第3行起：A列=数据2姓名，B列=数据1姓名
- 当无映射文件时，使用单词级模糊匹配（SequenceMatcher，阈值0.82）

## 数据合并优先级

| 场景 | 处理方式 |
|------|----------|
| 同日都有数据（数据1≥2次打卡） | 数据1优先 |
| 数据1仅1次打卡（缺卡） | 降级到数据2 |
| 仅有数据2 | 直接用数据2 |
| 仅有请假标记 | 标记为请假 |
| 无法识别标记 | 标记为"待确认" |
| 无数据 | 标记为无数据 |

### 异常标记
- **不满勤**: 实际工时 < 标准工时 - 0.15h（含容差）
- **异常缺卡**: 有系统打卡史的员工某日无系统数据，仅有线下数据
- **待确认**: 数据2中有无法识别的文字标记

## 蓝领规则

### 适用员工（9人）
ZAKIA TERFAS, ZUREL Samet, François Lippolis, Benjamin Torfs,
Tony Rocchia, ESQUIVEL Eduardo, Santos Raymundo, Barry Barry,
Sébastien Bernard

### 标准工时
- **每天标准**: 7.6小时
- **午休扣减**: 统一扣除 30分钟（0.5h）
- 含TOIL批注补足后的总工时与标准比较
- 蓝领每周周期：周一到周日（ISO周）
- 跨月合并：上月29-30日自动合并到当前月W27计算

### 加班池（周制，周一到周日为一个周期）

**重要规则：周总工时必须达到 38h，当日超过标准的部分才能计算调休或加班。**

| 周总工时 | 处理 |
|----------|------|
| < 38h | 所有日超时归零，不计调休也不计加班 |
| 38h ~ 40h | 超过38h的部分按 TOIL（调休）计算，上限2h |
| > 40h | 38h ~ 40h仍为TOIL（≤2h），超过40h的部分按加班费100% |

示例：某员工周一到周日打卡如下
| 日 | 实际 | 标准 | 超时 | 按旧规则 | 按新规则 |
|---|------|------|------|----------|----------|
| 周一 | 7.6h | 7.6h | 0h | 0h | 0h |
| 周二 | 8.0h | 7.6h | 0.4h | 0.4h TOIL | **0h** |
| 周三 | 10.0h | 7.6h | 2.4h | 1.6h TOIL + 0.8h OT100% | **0h** |
| 周四 | 10.0h | 7.6h | 2.4h | 2.4h OT100% | **0h** |
| 周日 | 2.0h | 7.6h | 0h | 0h | 0h |
| **周合计** | **37.6h** | **38h** | **5.2h** | TOIL 2h + OT 3.2h | **全部0** |

> 因为周总 37.6h < 38h，所有日超时都不算数。

每周加班池按天分配：先分配调休额度，超出部分转加班费。

## 白领规则

### 适用员工
除上述9人蓝领外的所有员工。

### 标准工时（5天分组制）
按有效出勤日（实际上班+非OFF的请假）每5天一组：

| 位置 | 标准工时 |
|------|----------|
| 每组第1-4天 | 7.5h |
| 每组第5天及以后 | 7.0h |

> 示例：某月有22个有效工作日，则 1-4天=7.5h, 5天=7.0h, 6-9天=7.5h, 10天=7.0h ...

- **午休扣减**: 统一扣除 30分钟（0.5h）
- 请假（含CM病假、VA年假、Congé mariage婚假等）计入工作日计数
- OFF（休息日）不计入工作日计数

### 加班池（周制，周一到周日为一个周期）

**重要规则：周总工时必须达到 37h，当日超过标准的部分才能计算调休或加班。**

| 周总工时 | 处理 |
|----------|------|
| < 37h | 所有日超时归零，不计调休也不计加班 |
| 37h ~ 38h | 超过37h的部分按 TOIL（调休）计算，上限1h |
| > 38h | 37h ~ 38h仍为TOIL（≤1h），超过38h的部分按加班费100% |

| VA | 年假 (Vacances Annuelle) | 计入工作日计数，视同出勤 | **是** ✅ |
| Récup heures supplémentaires | 调休假 | 计入工作日计数，视同出勤 | **是** ✅ |
| Récup férié | 节日补休 | 计入工作日计数，视同出勤 | **是** ✅ |
| Mi temps médical | 医疗半工 | 计入工作日计数，0工时 | 否 |
| OFF | 休息/排休 | 不计入工作日 | 否 |
| OFF demi journée am | 半天休息(上午) | 不计入工作日 | 否 |
| ABSENT | 缺勤 | 计入工作日计数，0工时 | 否 |
| Congé mariage | 婚假 | 计入工作日计数，视同出勤 | **是** ✅ |
| Férié | 公共假期 | 计入工作日计数，视同出勤 | **是** ✅ |
| *未知文字* | 待确认 | 标记为待确认，需人工识别 | — |

### 带薪假视同出勤

带薪假（婚假、年假、病假、公共假期、调休假）期间，员工**视同出勤**，标准工时时数计入周总工时参与门槛判断。

| 规则 | 说明 |
|------|------|
| 当天 actual_hours | 设为 std_hours（标准工时） |
| 参与周总工时计算 | **是** ✅ |
| 触发加班 | 否（actual=std，超时为0） |
| 白领工作日排序 | 计入（已计入） |
| 跨月合并 | 前月带薪假同样适用 |

#### 配置参数
```json
"paid_leave_types": ["VA", "CM", "Congé mariage", "Férié", "RECUP"]
```

#### 示例（Tania W27）
Tania（白领）6.29-7.1 休婚假，7.2-7.3 上班：

| 日期 | 状态 | actual_hours | std_hours | 计入周总 |
|------|------|-------------|-----------|---------|
| 6/29（前月合并） | 带薪假视同 | 7.5h | 7.5h | ✅ |
| 6/30（前月合并） | 带薪假视同 | 7.5h | 7.5h | ✅ |
| 7/1 | 带薪假视同 | 7.5h | 7.5h | ✅ |
| 7/2 | 上班 | 8.84h | 7.5h | ✅ |
| 7/3 | 上班 | 7.66h | 7.5h | ✅ |
| **W27合计** | | **39.0h > 37h** | | 达标触发加班 |

→ W27 TOIL池 = min(1, 39-37) = 1h；OT100池 = max(0, 39-38) = 1h
→ 7/2 超1.34h：1h调休 + 0.34h加班费 | 7/3 超0.16h：全部加班费

### 周总工时门槛（核心规则）

**周总工时必须达到门槛值**，当日超过标准的部分才能计算调休或加班。

| 类型 | 门槛 | 小于门槛时 |
|------|------|-----------|
| 蓝领 | 38h | 所有日超时归零，不计调休不计加班 |
| 白领 | 37h | 所有日超时归零，不计调休不计加班 |

#### 典型场景
假设某白领一周出勤4天：3天×7.5h + 1天×**9h（超1.5h）** = **31.5h < 37h**

→ 那天的 **9h 全部是 work**，超标准 1.5h
→ 但周总 31.5h **< 37h 门槛**
→ 这 **1.5h 超时完全归零**，不产生任何调休或加班费

**原理**：防止用某天的长时间来"凑"调休/加班，必须整体一周出勤量达标，单日多干不足为凭。

## TOIL（调休补足）规则

### Excel批注解析
当数据2的单元格中包含批注（Comment），自动扫描以下模式：

| 模式 | 解析 | 处理 |
|------|------|------|
| `2h30 de récup` | 2.5h TOIL | 加到实际工时 |
| `30 minutes de récupération` | 0.5h TOIL | 加到实际工时 |
| `TT` / `Télétravail` | 远程工作 | 显示标识，不计工时 |
| `Badge oublié` | 忘打卡 | 显示标识 |
| `Rdv médical` | 就医 | 显示标识 |

### TOIL作用
- TOIL作为补足工时加到实际工时上（目的是使不足的标准工时补满）
- 例如：某日实际在岗6.5h，批注含"1h récup" → 总工时 7.5h
- 批注含recup但无具体金额 → 标记为"NEEDS REVIEW"人工确认

## 数据容差

### 排班时间归零（Snap）
- 当数据2来源的工时与标准工时的偏差 ≤ 0.15h（9分钟）
- 强制归零到标准工时
- 原因：数据2是预排班时间，非精确打卡，微小偏差无意义

### 不满勤判定
- 实际工时 < 标准工时 - 0.15h 时标记为不满勤
- 0.15h 容差可避免时钟舍入导致的误报

## 法国规则

### 适用员工
所有员工（单一类别：standard）。

### 标准工时
- **每天标准**: 7.0小时（法定35小时工作周）
- **午休扣减**: 统一扣除 30分钟（0.5h）

### 加班费计算（周制，周一到周日为一个周期）

法国采用梯度加班费率，不设调休(TOIL)池。

| 周总工时 | 费率 | 处理 |
|----------|:----:|------|
| ≤ 35h | 0% | 正常工时，无加班费 |
| 35h ~ 43h | 125% | 超时部分按125%计算 |
| > 43h | 150% | 超时部分按150%计算（超出43h部分） |

### 请假类型

| 代码 | 含义 | 是否带薪 |
|------|------|:--------:|
| CP | 带薪年假 | ✅ |
| MAL | 病假 | ✅ |
| AT | 工伤 | ✅ |
| Férié | 公共假期 | ✅ |
| RTT | 减缩工时假 | ✅ |
| ABS | 缺勤 | ❌ |
| OFF | 休息 | ❌ |

## 自定义新国家

参考 `rules/example.json` 创建新的规则文件：

1. 复制 `rules/example.json` 为 `rules/{code}.json`
2. 修改以下关键参数：

```json
{
  "country": { "code": "cn", "name": "中国 (China)" },
  "employee_classes": [
    {
      "class_name": "standard",
      "standard_hours": { "type": "fixed_daily", "hours_per_day": 8.0 },
      "weekly_pool": {
        "normal_up_to": 40,      // < 40h 全部归零
        "toil_from": 40,
        "toil_up_to": 44,
        "overtime_100_above": 44, // > 44h 按加班费
        "overtime_rate": 1.5     // 加班费率150%
      }
    }
  ],
  "paid_leave_types": ["AL", "SL", "PH"],
  "leave_types": { "AL": "年假", "SL": "病假", "OFF": "休息", "ABS": "缺勤" }
}
```

3. 在 `config.json` 中设置 `"country": "cn"`
4. 运行 `python run.py --config config.json`

**无需修改任何代码！**

## 输出说明

生成的HTML日历包含：
1. **月份切换**：下拉框选择月份（6月/7月等，多月份数据嵌入）
2. **员工选择**：下拉菜单+搜索输入（月份切换时自动保留员工名）
3. **月度日历**：以周为行、日为列的网格视图（周一至周日）
4. **每日详情**：实际工时 / 标准分配 / 调休 / 加班费
5. **颜色编码**：白=正常, 黄=调休, 红=加班费, 蓝=请假/手工覆盖, 灰=周末/无数据
6. **企业信息栏**：员工姓名+类型标签（蓝领/白领）+月汇总数据
7. **周汇总**：每周工时分解（实际/标准/调休/OT100%）
8. **月度汇总**：正常、调休、加班费总计
9. **异常标记**：不满勤、缺卡、待确认，自动列出注意事项

### 生成方式

```bash
# 单月（向后兼容）
python build_html.py --config config.json

# 多月份切换（推荐）
python build_html.py \
  --input output_june/attendance_data.json --label "2026年6月" \
  --input output/attendance_data.json --label "2026年7月" \
  --output output/attendance_calendar.html
```
